# 分镜、配音、字幕与交付

## 信息设计

安排“吸引注意 → 故事 → 代表交互 → 技术依据 → 业务价值 → 结论”，可按网站特点重排，不固定章节数。维护分镜起止、旁白、对应素材、论点与来源。

每屏以画面为主：短标题 + 操作焦点 + 一个必要数据即可。删除重复介绍、长英文装饰语、与旁白同义的大段正文。业务只留易读分类，技术细节可依旁白逐段出现。必要来源与范围标注保持简短，详细证据去报告。

字幕放安全区，不遮挡关键 UI；技术名词按标准拼写显示。只有多个内容确实需要对比时才并排，否则顺序大画面更清楚。局部放大优先服务“看清哪里点、发生什么”，不要夸大成录制清晰度提高。

## 声音与时长

根据用途选清晰、自然且合适的音色。先用代表性短句试听，包含中文和英文技术名词；按当前配音服务的要求完成音色选择。具体音色与提供商作为一组使用，从当前工具读取，不复用旧会话令牌和临时 ID。

口播应像解释给人听，句子短，有语义停顿，避免播报式堆词。温柔不是极慢，也不是夸张气声。分章生成利于重做与对齐，保留规范技术术语用于字幕。

服务最终完成后获取真实音频并用 ffprobe 或可信最终元数据核实长度；初始 duration 可能只是估算。先修口播冗余，再微调语速或分镜，避免压缩到难听。任何截短都必须落在完整语义结尾，不能切半个词。

换音色后用新音频的实际词/句时间对齐字幕；ASR 会误认品牌和 Three.js 等，不用识别错误改写事实。规范文稿与时间戳对齐，检查缺词、错位、越界和重叠。不要按字数均分后声称精确对齐。

## 工程组织与验证

素材、分镜数据、字幕、组件分开。Remotion 动画由帧驱动并使用 composition fps；读取相应 Skill，优先沿用项目锁定版本。以局部预览/代表帧验证构图，再整片渲染；已获用户导出授权时完成文件交付。

检查：
- 每个关键动作的前/中/后，画面裁切、字幕、焦点和转场；无无关窗口、黑帧、文字溢出。
- 播放或使用可用音频能力检查发音、截断、重复/叠音；无法试听就明确已做哪些客观检查，不声称听过。
- 核实旁白实际结束 <= 分镜结束，字幕结束 <= 对应窗口，原站静音素材不误标有现场声音。
- ffprobe 核对导出时长、宽高、编码、fps、音轨；ffmpeg 全片解码排查损坏。输出帧率与采集帧率分别记录。
- 检查包内能找到引用素材、字幕和依赖文件；排除 node_modules、缓存、凭据和失败采集。

交付清晰命名的成片、可编辑工程、字幕、分析报告和来源/覆盖说明。返回可播放视频和绝对路径链接。用户只需要预览时先交互预览，不擅自发布到外部平台。
