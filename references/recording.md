# 录制真实操作，并留下可剪辑的素材

## 选择采集方式

先检查当前环境已授权的浏览器与原生应用操作工具。优先支持持续视频采集的录屏器或浏览器录制能力；遵守当前运行时对 UI 自动化的限制。先做短样片，验证动作期间确实有画面、分辨率足够、焦点稳定，才批量采集。

如果只能连续采集窗口截图后编码：记录每帧时间戳，按真实间隔重建。若压缩等待，记录剪掉的间隔；如统一倍速则注明倍速。明确实际采样率、关键操作期间缺帧、是否只保留前后状态，不能用输出文件的帧率冒充采集质量。

## 操作镜头表

为每项建立：`scene_id | action | before | expected_result | source_clip | in/out | coverage | limitation`。

一般保留操作前可定位的状态、动作全过程、结果稳定显示片刻，尾部再转场。鼠标/按键提示仅作说明，不能伪造不存在的操作。自动转场、点击、拖拽、键盘移动、长按、失败重试要分别检查。

先定位，再执行；使用当前页面状态确定坐标与缩放。Retina 像素、窗口逻辑尺寸、截图尺寸不可想当然按固定比例换算。窗口大小/工具栏改变后重新检查裁切。

持续按键与截图 API 可能在服务端串行执行；把两次调用放进并发 Promise 并不保证动作期间录到了画面。检验实际时间戳与帧变化，不能只看命令成功。

用户切换目标窗口时优先隔离录制会话或恢复目标焦点，并确认当前域名/窗口。无法稳定继续时，解释观察到的问题，再请求短暂不操作该浏览器；不要一开始要求用户停用电脑。

公开可见的场景直达入口可以用于分场景采集，清楚标记独立采集，不描述为连续通关。不要修改页面状态伪造成功。

## 选片与放大

1. 先确认素材内容和名称一致；从官方影片抽出的某帧不等于原站某个交互的录制。
2. 去掉工具栏和无关区域，保留角色、控制区、结果计数等判断依据。
3. 同时两段导致看不清时改为顺序展示。给录屏主要画幅，而非先把文字铺满再给视频留小角落。
4. 对真正操作的区域适当放大，起始可短暂展示全局再到局部。跟随位置稳定，避免为动而动的镜头；不放大到失焦、截头或把结果裁出边界。
5. 在接近实际观看尺寸下检查，不只看高清文件尺寸。放大不能补回缺帧、模糊或未录到的动作，必要时重新采集。

删除或隔离无关/失败画面，打包使用允许清单，只包含本项目需要的素材。覆盖表诚实写“完整动作 / 部分过程 / 前后状态 / 未录制”，保留必要限制说明。
